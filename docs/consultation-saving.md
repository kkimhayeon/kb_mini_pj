# 상담 답변 저장 및 계획 정보 반영

## 화면 사용

1. 답변 저장 화면에서 질문별 답변 원문을 입력합니다.
2. 필요한 경우 `계획 정보 입력 및 RM 확인`을 열고 사업 대상·범위, 상태, 금액·통화, 예정일·확정 범위를 입력합니다.
3. 다음 분석에 사용할 항목은 내용을 확인한 뒤 RM 확인 체크를 선택합니다. 답변이나 입력 항목을 수정하면 체크가 해제됩니다.
4. 저장 버튼으로 상담, 모든 질문과 답변, 입력한 계획 정보를 한 번에 저장합니다.

답변 원문만 저장해도 됩니다. 원문의 단어만으로 계획 상태를 자동 확정하지 않습니다. 계획 정보를 입력했지만 확인하지 않았다면 `PENDING`으로 보관하고 분석에는 사용하지 않습니다.

빈 항목과 `UNKNOWN` 상태는 기존 확인 정보를 삭제하지 않습니다. 기존 값을 지우는 기능은 아직 제공하지 않습니다. 금액은 원·달러 등 선택한 통화의 기본 단위로 입력합니다. 예를 들어 100억원은 `10000000000 KRW`입니다. 일정이 월/분기/반기/연 단위라면 해당 기간에 속하는 날짜와 확정 범위를 선택합니다.

## API

`POST /api/companies/{companyId}/consultations`의 `questions` 항목에 선택적인 `answer`를 포함할 수 있습니다. 질문 문장 비교나 별도 PATCH 없이 각 질문에 답변을 연결합니다. 기존의 답변 없는 상담 생성 및 개별 답변 PATCH도 유지됩니다.

```json
{
  "channel": "OTHER",
  "consultantName": "RM",
  "questions": [{
    "planId": 11,
    "questionSource": "AI_GENERATED",
    "questionText": "투자 규모는 얼마입니까?",
    "answer": {
      "answerStatus": "ANSWERED",
      "answerText": "100억원입니다.",
      "answeredBy": "고객",
      "planFact": {
        "planId": 11,
        "domain": "INVESTMENT",
        "planStatus": "PLANNED",
        "amount": "10000000000",
        "currency": "KRW",
        "extractionMethod": "RM_ENTERED",
        "verificationStatus": "RM_CONFIRMED",
        "rmConfirmed": true
      }
    }
  }]
}
```

- `answer: null`은 미답변 질문, `planFact: null`은 답변 원문만 저장한다는 의미입니다.
- `RM_CONFIRMED`는 연결된 계획과 명시적 `rmConfirmed: true`를 요구합니다. 이는 입력 확인 신호이며 사용자 인증·권한 확인을 대신하지 않습니다.
- 금액과 통화, 예정일과 확정 범위는 각각 쌍으로 전달합니다. 큰 금액의 소수 정밀도를 유지하기 위해 프론트엔드는 금액을 문자열로 전송하고 서버는 `BigDecimal`로 저장합니다.
- 잘못된 항목이 하나라도 있으면 요청 전체를 롤백합니다. UI는 실패 시 입력 내용을 유지합니다.
- 저장 중 중복 클릭은 차단하지만, 통신 단절 후 요청 재전송에 대한 서버 측 중복 방지는 아직 제공하지 않습니다.

## 다음 분석

확인된 정보 중 적용 시점이 도래한 항목을 계획 ID별로 합칩니다. 같은 항목은 적용 시점이 최신인 값, 시점이 같으면 나중에 저장된 값을 사용합니다. 대상·상태·금액/통화·예정일/확정 범위는 각각 합치므로 나중에 일정만 입력해도 이전 금액은 유지됩니다. 서로 다른 계획의 정보는 섞지 않습니다. 여러 계획을 같은 공시와 정밀하게 대응시키는 기능은 후속 분석 고도화 범위입니다.

기존 `plan_fact.amount`, `plan_fact.currency` 컬럼을 사용하므로 현재 `schema.sql` 기준 추가 테이블 변경은 없습니다.

## 검증 범위

`ConsultationServiceTest`는 별도 H2 테스트 DB에서 실제 JPA 저장과 트랜잭션 롤백을 검증합니다. 운영 PostgreSQL 연결이나 외부 OpenDART/Gemini 호출은 사용하지 않습니다. 프론트엔드 테스트는 RM 확인, 입력 변경 시 확인 해제, 한 번의 저장 요청, 저장 실패 시 입력 유지 등을 검증합니다.
